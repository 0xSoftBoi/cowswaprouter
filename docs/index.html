MEV Protection

Orders settle through CoW Protocol's batch auction instead of directly through an AMM — searchers can't front-run what isn't on-chain yet. Price is determined off-chain by solver competition.

Transaction Flow

Four steps, one transaction

depositAndSettle() executes the entire flow atomically.

01

Pull tokens

transferFrom(owner, router, amount)

Brings the tokens on-chain into the router contract from the owner's wallet.

02

Approve relayer

approve(cowRelayer, amount)

Grants the CoW vault relayer permission to move the tokens for settlement.

03

Deposit

ICowVaultRelayer.deposit(token, owner, amount)

Registers funds with CoW's settlement infrastructure. Tokens are now ready for batch auction.

04

Settle (optional)

ICowSettler.settle(orderUid)

Finalizes the batch auction order. Pass empty bytes to leave pending in the CoW queue.

Why Batch Auctions?

CoW vs direct AMM

Batch auctions eliminate the conditions that make MEV possible.

✓ With CoW Protocol
✓ Price determined off-chain by solvers
✓ Uniform clearing price for all batch orders
✓ Front-running impossible — no on-chain exposure
✓ Solver competition returns surplus to user
✓ Optional settlement — order can wait
✗ Direct AMM swap
✗ Price set by on-chain mempool state
✗ Earlier txs get better prices
✗ Sandwich attacks extract value
✗ MEV surplus goes to searchers
✗ Must settle immediately or cancel
